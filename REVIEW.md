# Код-ревью плагина Sentinel-2 MPC Downloader

**Версия ревью:** 0.2.0 → 0.3.0
**Объём:** 12 Python-модулей, ~1500 строк (без учёта ресурсов)
**Дата:** 2026-10-08

---

## 1. Резюме

Плагин решает чётко очерченную задачу (поиск Sentinel-2 L2A через STAC Microsoft
Planetary Computer → докачка нужных каналов → сборка синтезов/индексов) и в целом
написан добротно: чистое разделение слоёв (Qt-диалоги / Qt-free пайплайн / GDAL),
фоновые потоки с сигналами вместо заморозки UI, атомарная запись кеша токенов,
паттерн `.part` + rename при скачивании, корректный учёт BOA-смещения
(processing baseline ≥ 04.00) при расчёте NDVI/NDMI, пос.strip-обработка индексов
без загрузки всего растра в память.

Основные проблемы, найденные ревью: **риск падения всего QGIS** при закрытии
диалога во время длинной GDAL-операции, **новая HTTP-сессия на каждый файл**
(лишние TCP+TLS-рукопожатия), **отсутствие пагинации STAC** (тихая обрезка
выдачи первой страницей), **«докачка» только на уровне файлов** (`.part`
удалялся при отмене/обрыве), **гонка в кеше SAS-токенов** и потеря текста
ошибок GDAL. Все перечисленные дефекты исправлены; полный список — ниже.

- Разделение `pipeline` (Qt-free) и диалогов — тестируемо и переиспользуемо.
- `Worker` на сигналах (`progress/item/succeeded/failed`) — корректный Qt-паттерн.

## 3. Детали исправлений

### C1. Падение при закрытии диалога во время работы 🔴

`Worker.stop(timeout_ms=5000)` откладывал `cancel()` и ждал до 5 секунд, но
GDAL-операции (`gdal.Warp`, `gdal.Translate` на ~700 МБ) не проверяют отмену и
легко могут длиться дольше. После таймаута диалог закрывался, а `Worker` был
**дочерним QObject диалога** → QThread уничтожался при живом потоке →
`QThread: Destroyed while thread is still running` → abort всего процесса QGIS.

**Исправление:** `stop()` теперь возвращает `bool`; если поток не завершился,
вызывается новый `Worker.detach()` — отключение всех сигналов, снятие
parent-связи, парковка ссылки на уровне модуля (`_detached`), авто-`deleteLater`
по `finished`. Применено в `MainDialog.closeEvent`, `SceneDialog.done`.
`plugin.unload()` защищён транзитивно через `closeEvent`.

### C2. Отмена в `build_index` 🔴

В старом коде при отмене: `dst = None` → `out_path.unlink(...)` → `raise
Cancelled`. Но ссылка `band` (и внутренние ссылки SWIG) держала файл открытым:
на Windows `unlink` давал `PermissionError`, которое **затирало** `Cancelled` и
всплывало как ошибка. Теперь закрытие `band/dst/ds_a/ds_b` вынесено в `finally`,
удаление файла — в `except Cancelled` **после** закрытия, с защитой `except OSError`.

### H1. Переиспользование HTTP-сессий 🟠

`make_session()` вызывался в `_download_one` (на каждый канал!), `search`,
`get_token`. Каждый вызов — новый пул: TCP+TLS-рукопожатие (~0.3–1 с) на файл.
Для сцены с 10–12 каналами и ретраями — десятки секунд впустую.

**Исправление:**
- `net.shared_session()` — процессная сессия для API-вызовов (STAC, SAS-токен);
- `downloader.download()`/`download_thumbnails()` создают **одну** сессию на
  батч с `pool_maxsize=2×workers` и закрывают её в `finally`;
- увеличен пул адаптера (`pool_connections/pool_maxsize`) под параллельных воркеров.

### H2. Пагинация STAC 🟠

`search()` отправлял один POST и возвращал `features` как есть — сервер
отрезал всё сверх первой страницы. **Исправление:** цикл до `limit`
уникальных фич или исчерпания `next`-ссылок (макс. `max_pages=10` → до ~1000
сцен), дедупликация по `id`, поддержка обоих стилей next-ссылок (stac-server
`body`+`merge` и GET-ссылки с токеном), страница ограничена 100 (`PAGE_SIZE`).
Чтобы 1000 превью не устроили DDoS на рендер-API, диалог сцен качает превью
только для первых `THUMB_MAX=150` сцен (сцены отсортированы newest-first).

### H3. Настоящая докачка (HTTP Range) 🟠

Раньше `.part` удалялся при **любом** исключении, включая отмену и обрыв
соединения. **Исправление:** `.part` сохраняется; при следующем запуске
отправляется `Range: bytes=<size>-`:
- `206` → докачка (`open("ab")`), ожидаемый размер = offset + Content-Length;
- `416` → `.part` протух/разросся → удаление и один перезапуск с нуля;
- `200` (сервер игнорирует Range) → перезапись с нуля, содержимое корректно;
- пустой `.part` (0 байт) удаляется, мусор не накапливается.

Прогресс-колбеки согласованы с resumed-offset (суммарные байты учитывают
уже докачанную часть).

### M1–M7. Прочее 🟡

- **M1** `get_token` обёрнут в `threading.RLock` (поиск и пайплайн ходят за токеном параллельно).
- **M2** `processor._err()` добавляет `gdal.GetLastErrorMsg()` в текст `RuntimeError`.
- **M3** `resample_bands(..., cancelled, max_workers=3)` — пул потоков
  (GDAL отпускает GIL внутри Warp); проверка отмены до/после; `shutdown(cancel_futures=True)`
  с fallback для Python < 3.9.
- **M4** Ключи сцен collision-safe (`id#i`), ключ хранится в `Qt.UserRole`
  скрытой колонки; имя файла превью = `sanitized_id + md5[:8]`.
- **M5** Кап `min(40, ...)` в прогрессе загрузки; `dict.fromkeys` при удалении каналов.
- **M6** `_safe_name()` для папки сцены и имён файлов (для S2-идентификаторов поведение не меняется).
- **M7** `_prune_thumb_cache()` — держит не более 400 файлов по mtime.

## 4. Ожидаемый эффект

| Оптимизация | Эффект |
|---|---|
| Сессия на батч | −0.3…1 с × N файлов на сцену (N≈10–12); для превью — заметнее всего |
| Параллельный ресемплинг | этап «Resampling» ускоряется ~×2–3 (6 каналов 20/60 м) |
| Range-докачка | после обрыва — докачка остатка вместо повторных ~0.7 ГБ на канал |
| Пагинация STAC | сцены за пределами первой страницы больше не теряются |

## 5. Верификация

- `python -m py_compile` — все 12 модулей компилируются.
- 43 автотеста (Qt/GDAL-free части): локальный HTTP-сервер с поддержкой Range —
  полная загрузка, переиспользование готового файла, докачка 206, игнор Range
  сервером, отмена с сохранением `.part` и последующая докачка, 404 →
  `DownloadError`, батч из 3 файлов; парсеры STAC (next-ссылки обоих стилей,
  `dn_scale_offset`, fallback-имена каналов, MGRS-тайлы); `required_bands`;
  ISO-парсинг токен-кеша. **Все тесты пройдены.**
- Модули с зависимостями `qgis`/`osgeo` (`processor`, `worker`, диалоги,
  `loader`, `plugin`) проверены компиляцией; рекомендуется ручной чеклист ниже.

### Чеклист ручной проверки (в QGIS)

1. Поиск с AOI и датами → таблица сцен, сортировка по облачности/дате, превью грузятся.
2. Download and build → прогресс, слои добавлены, NDVI/NDMI раскрашены палитрой.
3. Отмена на этапе «Downloading…» → статус Cancelled, в папке остались `.part`;
   повторный запуск той же сцены и синтеза → докачка (в логах/по времени видно,
   что заново качаются только недокачанные каналы).
4. Закрытие диалога на этапе «Building…» (крупная сцена) → QGIS не падает;
   через несколько секунд процесс спокойно завершает фон.
5. Поиск по AOI с заведомо >100 сценами (месяц, облачность 100%) → в таблице
   появляются сцены старше первой сотни.
6. Проверить, что другие плагины, использующие GDAL, работают как раньше
   (глобальный `gdal.UseExceptions()` по-прежнему не вызывается).

## 6. Рекомендации на будущее (не входит в 0.3.0)

1. **Сохранять даты поиска** в QSettings вместе с облачностью/папкой (L1).
2. **Пере-подпись URL при 401/403**: поймать ошибку канала, обновить токен и
   повторить файл (L2).
3. **8-бит RGB с LUT-растяжкой** на этапе сборки — файлы меньше в 2–4 раза,
   быстрее отрисовка; хранить DN-версию опционально (L3).
4. **Чтение окна AOI через /vsicurl** (GDAL умеет HTTP Range сам): качать не
   всю сцену, а только вырезку — главный резерв экономии трафика (L4).
5. **i18n-каркас** (.ts/.qm) при публикации плагина (L5).
6. Токен и превью кешируются в одном JSON-файле — при мультипоточном росте
   стоит перейти на `QStandardPaths.CacheLocation` + файловый лок (fcntl/msvcrt),
   если плагин запускается в двух экземплярах QGIS одновременно.
