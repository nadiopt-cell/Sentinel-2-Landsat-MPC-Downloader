## 1. Резюме

Версия 0.4.0 добавила Landsat чисто и без регрессий: реестр миссий изолирован в `landsat.py`, `processor.py`/`pipeline.py` параметризованы (spec-словари, `band_res`, `target_res`), Sentinel-2-ветка не тронута, все обещания README/метаданных соответствуют коду. Архитектурный костяк 0.3.0 (Qt-free пайплайн, `.part`+Range-докачка, пагинация STAC, thread-safe кеш токенов, `Worker.detach()`) сохранён и работает.

Найдена **одна высокоприоритетная проблема**: импорт `QAction` из `QtWidgets`, который в PyQt6 (а значит в QGIS 4) отсутствует — **плагин не загрузится в QGIS 4 вообще** (исключение при `initGui`), хотя `qgisMaximumVersion=4.99` это обещает. Фикс — три строки. Критических проблем нет; остальное — defensive-мелочи, расхождение комментария с кодом в `build_index` при отмене, мёртвый код и косметика.

**Итоговая оценка:** код готов к использованию в QGIS 3.28–3.4x; для честного заявления поддержки QGIS 4 нужно исправить H1 (и желательно M1–M2). Качество тестового покрытия — хорошее для Qt-free слоёв, есть 4 конкретных пробела (раздел 8).

## 3. Детали находок и исправления

### H1. `QAction` из `QtWidgets` — плагин не загрузится в QGIS 4 🟠

```python
# plugin.py:6
from qgis.PyQt.QtWidgets import QAction, QMessageBox
```

`qgis.PyQt` — это только выбор биндинга (PyQt6 → PyQt5), без шимминга атрибутов. В Qt6/PyQt6 класс `QAction` перенесён из `QtWidgets` в `QtGui` (официальное breaking change PyQt6), поэтому в QGIS 4 импорт упадёт с `ImportError` ещё на `initGui`, и QGIS пометит плагин как нерабочий. Остальной Qt-код написан в правильном кросс-стиле (scoped-enum'ы вида `Qt.ItemDataRole.UserRole`, `exec()` вместо `exec_()`), `loader.py` корректно ветвится по `hasattr(Qgis, "ShaderInterpolationMethod")` — H1 единственное место, ломающее обещанную поддержку 4.x.

**Исправление** (паттерн «Qt6 first, Qt5 fallback»):

```python
# plugin.py
try:
    from qgis.PyQt.QtGui import QAction        # Qt6 / QGIS 4
except ImportError:
    from qgis.PyQt.QtWidgets import QAction    # Qt5 / QGIS 3.x
```

После фикса обязательно проверить загрузку плагина в QGIS 4 вручную (чеклист, раздел 9).

### M1. Порядок `except`/`finally` в `build_index` 🟡

```python
# processor.py:254-264
except Cancelled:
    # комментарий: «finally ниже закрывает датасеты ПЕРВЫМ делом»...
    try:
        out_path.unlink(missing_ok=True)
    except OSError:
        pass
    raise
finally:
    band = dst = ds_a = ds_b = None
```

Python выполняет блок `except` **до** `finally`, поэтому `unlink()` вызывается, пока `dst`/`band` ещё держат файл открытым. На Linux файл удалится (открытый дескриптор не мешает), на Windows `unlink` упадёт с `PermissionError`, который молча глотается `except OSError` — и частичный GeoTIFF остаётся на диске. Худших последствий нет (`Create` при следующем запуске перезапишет файл; `Cancelled` не теряется — основная часть фикса C2 из 0.3.0 работает), но комментарий описывает несуществующий порядок, а «тихий» неудавшийся unlink — это мусор в папке сцены.

**Исправление** — закрыть хендлы в самом `except`:

```python
except Cancelled:
    band = dst = ds_a = ds_b = None   # реально закрываем до unlink
    try:
        out_path.unlink(missing_ok=True)
    except OSError:
        pass
    raise
finally:
    band = dst = ds_a = ds_b = None   # остаётся для не-Cancelled путей
```

### M2. `_take_from_canvas` без обработки ошибок трансформации 🟡

`main_dialog.py:247–257`: `transformBoundingBox()` бросает исключение для вырожденных/датлайн-пересекающих экстентов (например, холст в CRS с долготой ±180 при масштабе всего мира). Исключение в слоте кнопки не роняет QGIS, но пользователь получает «кнопка не работает» плюс traceback в консоль. Обёртка в `try/except` c `QMessageBox.warning(self, "Extent error", str(e))` — четыре строки, чинит UX полностью.

### M3. Блокирующий `RLock` на время сетевого refresh токена 🟡

`token_cache.get_token` держит `threading.RLock` во время `shared_session().get(...)` (таймаут 30 с × до 4 ретраев с бэкоффом ≈ до ~2 мин худшего случая). Поток, параллельно запрашивающий токен (поиск сцен при активном скачивании или наоборот), молча ждёт. TTL токенов MPC 30–60 мин, коллизии редки, так что это трейдофф, а не баг. Если захочется убрать ожидание: ввести «refresh in progress»-событие — конкурентный поток при протухшем кеше либо дожидается события, либо получает протухший токен с пометкой (токен обычно валиден ещё минуты после expiry-margin). Минимум — задокументировать блокировку в docstring.

### L1–L8. Низкий приоритет

- **L1** `stac_client.py:55`: после GET-страницы `payload = None`; если следующая next-ссылка окажется в стиле POST+`merge`, `dict(current_payload)` бросит `TypeError`. Оба реальных сервера консистентны в стиле, но защитный `dict(current_payload or {})` бесплатен.
- **L2** `scene_dialog.py:134`: `round(float(cc), 1)` без `try`. У обоих коллекций MPC поле числовое, но одна нестандартная сцена с строковым значением сделает нераскрываемым весь диалог. Дешёвый фикс: `try: ... except (TypeError, ValueError): cc_item.setText("-")`.
- **L3** `scene_dialog.py:53`: `files.sort(key=lambda p: p.stat().st_mtime)` — файл, удалённый между `iterdir()` и `stat()` (антивирус, второй экземпляр QGIS), уронит конструктор диалога. Безопасный key: `lambda p: (p.stat().st_mtime if p.exists() else 0)` или stat в try.
- **L4** `main_dialog.py:53–54`: дефолтная папка `~/Sentinel2_MPC` вводит в заблуждение при скачивании Landsat. Менять стоит аккуратно: у существующих пользователей значение уже в QSettings (перекрывает дефолт), новый дефолт увидят только новые установки — например `MPC_Downloader`.
- **L5** `syntheses.py:97–99` `bands_to_resample()` больше не вызывается продакшн-кодом (проверено grep) — остаток API до перехода на `band_res`; `token_cache.clear_cache()` используется только тестами. Либо удалить, либо пометить как публичную утилиту. Мёртвый код в 2100-строчном проекте — дешёвая плесень, лучше срезать.
- **L6** `__init__.py:1` — docstring всё ещё «Sentinel-2 MPC Downloader»; `plugin.py:30` — меню `&Sentinel`. Оба места созданы до Landsat; для целостности: docstring `Sentinel-2 & Landsat MPC Downloader`, меню `&Sentinel / Landsat` (или нейтральное `&MPC Downloader`).
- **L7** `processor.py:83`: `multithread=True` внутри `gdal.Warp` при внешнем `ThreadPoolExecutor(max_workers=3)` даёт до 3×N тредов GDAL на ядрах поменьше. При `max_workers > 1` разумно передавать `multithread=False` (или число тредов GDAL = `cpu_count // workers`). На типичных десктопах незаметно.
- **L8** `pipeline.py:90–92`: scale/offset читается от red-канала и применяется к обоим каналам NDVI. Для Landsat C2 L2 это строго верно (все reflectance-ассеты делят одну сетку 2.75e-05/−0.2), для S2 — тоже (единый baseline-оффсет), но допущение стоит зафиксировать однострочным комментарием в `pipeline.run`, чтобы будущий индекс с разными масштабами (например, NDSI с SWIR) не унаследовал молча неверный оффсет.

## 5. Корректность Landsat-логики

Проверено и подтверждено (включая живой E2E от 2026-10-19):

- **Коллекция и миссии:** `landsat-c2-l2` действительно содержит только Landsat 4–9 (TM/ETM+/OLI); Landsat 1–3 (MSS) на Planetary Computer отсутствуют — это честно отражено в UI-заметке, README и changelog, а не замолчано. `platform`-фильтр уходит серверной частью запроса (`{"in": [...]}`) — миссии не смешиваются.
- **Бэнды:** шесть reflectance-каналов (`blue, green, red, nir08, swir16, swir22`) есть у всех миссий на единой сетке 30 м; `coastal` — только OLI (8/9), `lwir` — только TM/ETM+ (4/5/7), и у 8/9 тепловой канал корректно **не предлагается** (в L2SR-сценах его нет). E2E: у сэмплов L9/L5/L4/L7 отсутствующих ассетов нет.
- **Продукты по требованиям:** L8/9 и L5/7 — 4 стандартных синтеза + NDVI; L4 — только True/False Color + поканальные загрузки (индексы скрыты в UI и отвергаются в `pipeline.run` повторной валидацией — защита от рассинхрона UI и пайплайна двойная).
- **NDVI:** `nir08`/`red` — корректная пара для TM/ETM+/OLI; масштабирование `DN·0.0000275 − 0.2` читается из `raster:bands` ассета с правильным фолбэком на константы C2 L2 (и отдельно — baseline-логика −1000·0.0001 для Sentinel-2 ≥ 04.00).
- **WRS-2:** `feature_tile_id` форматирует `path/row` как `095/022` (int→3 знака) с фолбэком на строковые значения; MGRS-логика для S2 не задета.
- **Замечание (не дефект):** если у отдельной сцены 8/9 отсутствует `coastal`, ошибка «Scene has no asset for band coastal» всплывёт только при скачивании — до поиска это неизвестно. Терпимо; можно улучшить подсказкой «снимите канал с выделения» в тексте ошибки.

## 6. Потокобезопасность и GDAL

- `Worker` + `detach()` не изменились с 0.3.0 и остаются правильным паттерном: сигналы — queued, `report()` безопасно вызывается из потоков `ThreadPoolExecutor` внутри пайплайна.
- `dn_scale_offset`, `get_asset_href`, `signed_url` — чистые функции над dict, в потоках безопасны.
- GDAL-дескрипторы закрываются в `finally` в `resample_band`, `build_rgb` (косвенно, через `vrt = None`), `build_index` — с нюансом M1. `gdal.UseExceptions()` по-прежнему не включается глобально, ошибки вытаскиваются через `GetLastErrorMsg()` — поведение для других плагинов QGIS не меняется.
- `_download_one` рекурсивный повтор после 416 ограничен одним шагом (`.part` удалён → `resume=False` → второй 416 невозможен) — переполнения стека нет.
- Расовая ситуация в `resample_bands`: при отказе одного будущего остальные продолжают писать свои `.part`-файлы — безвредно (каждая пара «бэнд→файл» уникальна), при следующем запуске докачка/переиспользование сработает.

## 7. Qt5/Qt6 и версии Python

- Все обращения к enum'ам — в scoped-форме (`Qt.ItemDataRole.UserRole`, `QDialogButtonBox.StandardButton.Ok`), работающей и в PyQt5.15, и в PyQt6. `exec()` (не `exec_()`), `calendarPopup`-kwarg, `QPixmap.scaled` — совместимы.
- Единственный Qt6-блокер — H1 (см. выше).
- `Path.unlink(missing_ok=True)` требует Python ≥ 3.8; QGIS 3.28 несёт Python 3.9, QGIS 4 — новее. Нижняя граница соблюдается; `qgisMinimumVersion=3.28` корректен.
- `loader._linear_interpolation()` корректно ветвится для QGIS ≥ 3.34 / 4.x.

## 9. Производительность, безопасность, документация

**Производительность.** Скачивание: 4 воркера на батч, одна сессия, пул 8 — для сцены Landsat (6–8 файлов × ~40–70 МБ) узкое место — канал, не клиент. Сборка NDVI полосами по 512 строк — память ограничена независимо от размера сцены. Compress DEFLATE + правильные предикторы (2 для uint16, 3 для float32). Оверсабскрипшн Warp — L7. Серьёзных резервов в горячем пути не видно; крупные оптимизации (8-бит LUT-синтезы, `/vsicurl`-вырезки по AOI) из рекомендаций 0.3.0 остаются главными и для 0.4.x.

**Безопасность.** Секретов в коде нет; SAS-токен не попадает в сообщения об ошибках (`u.split('?')[0]` в `downloader.download` — хорошо). Токен хранится в `sentinel_mpc_cache.json` в профиле QGIS открытым текстом — приемлемый трейдофф для короткоживущих (30–60 мин) токенов локального плагина; при желании — `QStandardPaths.CacheLocation` + файловый лок (рекомендация 0.3.0 остаётся актуальной при запуске двух экземпляров QGIS). Превью качаются с подписанными blob-URL, кеш превью ограничен 400 файлами.

**Документация.** README точен и синхронизирован с кодом (таблица продуктов по миссиям соответствует `landsat.MISSIONS`/`PRODUCTS`, включая запрет индексов для L4 и отсутствие L1–3). `metadata.txt`: версия, теги, description и подробный changelog — в порядке. Расхождения — только L4/L6.
